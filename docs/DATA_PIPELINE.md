# Data Pipeline

End-to-end path implemented in `src/pipeline/video_pipeline.py` (`VideoEditorialPipeline.run`).

~~~mermaid
flowchart LR
  V[Video file] -->|validate ext/size| X[FFmpeg: 16 kHz mono WAV]
  T[Transcript JSON / timestamped text] --> S
  X -->|optional local Whisper| T
  S[Segmenter] --> F[Acoustic + lexical features]
  X --> F
  F --> M[DistilBERT + LoRA + 3 heads]
  M --> E[Evidence-grounded synthesis]
  E --> J[JSON / Markdown / HTML report]
~~~

| Stage | Module | Notes |
|---|---|---|
| Video validation | `video_pipeline.py` | Supported extensions and size check; clear errors for unsupported files |
| Audio extraction | `src/audio/extractor.py` | Requires `ffmpeg` on PATH; otherwise acoustic features are estimated from text |
| Transcript | `video_pipeline.py` | Provided transcript (JSON segments, `[MM:SS]` text, or plain text). If only a video is given, local `openai-whisper` is used **if installed**; otherwise the run fails with an explanatory error |
| Segmentation | `src/data/segmenter.py` | Timestamped segments, or adaptive sentence-window segmentation |
| Features | `src/audio/extractor.py`, `src/data/feature_engineering.py` | WPM, silence ratio, RMS energy, filler-word density, lexical stats |
| Inference | `src/models/` | Hook probability, drop-off risk, quality (1–10) per segment |
| Synthesis | `video_pipeline.py` | Rules over evidence (WPM, silence, fillers) + model scores → risks and recommendations, each with its evidence dict |
| Reports | `src/pipeline/report_generator.py` | JSON (machine-readable), Markdown, standalone HTML |

## Semantics of the outputs

- `metadata.model_status`: `fine_tuned` when a checkpoint was loaded, `untrained_heads` otherwise. With untrained heads the scores are random; the UI, Markdown report and Node bridge show a warning.
- `retention_curve[].modeled_retention_index`: heuristic index (starts at 100) accumulated from per-segment drop-off scores. **Not** a measured or calibrated audience-retention percentage.
- Risk / hook scores are uncalibrated model outputs from a checkpoint trained on synthetic data.

## Training data

`src/data/dataset.py::generate_curated_editorial_dataset` produces synthetic samples from 10 templates (each sample has a `group_id`). To train on real data, pass `--dataset-path` with a JSON list of objects containing `text`, `hook_label`, `drop_off_risk`, `quality_score`, acoustic features and ideally a `group_id`/`video_id` so the group-aware split keeps one video's segments in one split.

## Sample assets

`examples/sample_video.mp4` is generated by `examples/generate_sample_video.py` (440 Hz tone with silent gaps, no speech), so its acoustic evidence (WPM 0, silence 100% in later segments) reflects the synthetic audio, not the transcript.
